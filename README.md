# فیلکس | Feelks

نسخهٔ قابل بررسی یک وب‌سایت فارسی، راست‌به‌چپ و تک‌صفحه‌ای برای معرفی خدمات فیلکس. این پروژه با HTML، CSS و JavaScript ساخته شده و به نصب وابستگی یا مرحلهٔ build نیاز ندارد. انتشار عمومی و اتصال دامنه انجام نشده است.

پیش‌نمایش زندهٔ خصوصی: https://feelks-preview.shhbsaremi.chatgpt.site — ورود با حساب مالک لازم است.

مرجع پرینتیا از طریق HTML و محتوای متنی بررسی شد؛ بررسی بصری کامل آن انجام نشد. طراحی مستقل بر پایهٔ فضای سفید، کارت‌های منظم، گوشه‌های گرد و رنگ آبی‌بنفش انجام شده است. نشان نوشتاری و رنگ‌ها فعلاً موقت و قابل تغییرند.

نسخهٔ اجرایی در عرض‌های ۳۲۰، ۳۷۵، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ پیکسل با مرورگر Chromium بررسی شده است. اسکرول افقی، خطای جاوااسکریپت یا تصویر بارگذاری‌نشده در بررسی نهایی دیده نشد. منوی موبایل، لینک‌ها، انتخاب خدمت، پرسش‌های بازشونده و اعتبارسنجی شماره‌های فارسی، عربی و انگلیسی آزمایش شدند. در حالت پیش‌نمایش، هیچ درخواست ارسال فرم یا ذخیرهٔ اطلاعات انجام نشد.

## اجرا و مشاهده

بستهٔ ZIP پروژه را استخراج کنید و در پوشهٔ پروژه اجرا کنید:

```bash
python -m http.server 8080 --directory dist
```

سپس `http://localhost:8080` را باز کنید. باز کردن مستقیم فایل `dist/index.html` در مرورگر نیز برای بررسی نسخهٔ فعلی کار می‌کند. برای آزمایش اتصال واقعی فرم، از وب‌سرور استفاده کنید.

تمام فایل‌های اجرایی داخل `dist` هستند؛ برای جابه‌جایی یا میزبانی، این پوشه را با ساختار و دارایی‌هایش کامل کپی کنید. فایل‌های راهنما جزو فایل‌های اجرایی نیستند.

## ویرایش

| فایل | کاربرد |
| --- | --- |
| `dist/config.js` | رنگ‌های تأکیدی، اطلاعات تماس، مسیر تصاویر و مقصد فرم |
| `dist/content.js` | متن کارت‌ها و جزئیات سه خدمت، مزیت‌ها، مراحل همکاری و پرسش‌ها |
| `dist/index.html` | تیتر و متن آغازین، سربرگ، تجربهٔ دیجی‌پی، فرم، پاورقی و اطلاعات سئوی صفحه |
| `dist/styles.css` | چیدمان، اندازه‌ها، حالت‌های واکنش‌گرا و فونت محلی |
| `dist/app.js` | ساخت بخش‌ها، منوی موبایل، انتخاب خدمت و اعتبارسنجی/ارسال فرم |
| `dist/assets/` | تصاویر، فونت و نشان مرورگر |

شماره، ایمیل و آدرس در `config.js` خالی هستند و تا زمان تکمیل نمایش داده نمی‌شوند. اینستاگرام روی `feelks.cafe` تنظیم شده است. رنگ آبی‌بنفش و نشان نوشتاری فعلی موقت‌اند. پس از تغییر هویت، رنگ `theme-color` و نشان مرورگر را نیز هماهنگ کنید.

تصاویر فعلی برای معرفی حال‌وهوای خدمات‌اند و عکس پروژه‌های فیلکس نیستند. بخش دیجی‌پی صرفاً متنی است و لوگو، نقل‌قول یا نتیجهٔ ساختگی ندارد. هنگام جایگزینی تصاویر، نسخهٔ بهینهٔ WebP، متن جایگزین و توضیح واقعی تصویر را با هم به‌روز کنید. برای تصویر آغازین، مسیر پیش‌بارگذاری داخل `index.html` را هم هماهنگ نگه دارید.

لینک مستقیم بخش‌ها: `#services`، `#workplace`، `#cafe`، `#events`، `#experience`، `#process`، `#faq` و `#contact`. شناسه‌های سه خدمت را ثابت نگه دارید؛ دکمه‌های همکاری از آن‌ها برای انتخاب نوع خدمت استفاده می‌کنند.

## اتصال فرم واقعی

در پیش‌نمایش، `form.endpoint` برابر `null` است. دکمه فقط اعتبارسنجی می‌کند؛ هیچ درخواست شبکه، ذخیره‌سازی اطلاعات یا پیام ثبت موفقی انجام نمی‌شود.

برای فعال‌سازی، یک سرویس واقعی با نشانی HTTPS آماده و آزمایش کنید؛ سپس نشانی آن را در `dist/config.js` قرار دهید:

```js
form: { endpoint: 'https://your-domain.example/api/cooperation' }
```

نشانی بالا فقط نمونهٔ ساختار است و باید با مقصد واقعی جایگزین شود. فرانت‌اند درخواست `POST` با `Content-Type: application/json` می‌فرستد:

```json
{
  "fullName": "نام و نام خانوادگی",
  "phone": "09123456789",
  "company": "نام مجموعه",
  "service": "workplace",
  "need": "توضیح نیاز"
}
```

`fullName`، `phone` و `service` الزامی‌اند؛ `company` و `need` اختیاری‌اند. مقادیر خدمت: `workplace` برای درون‌سازمانی، `cafe` برای راه‌اندازی کافهٔ عمومی و `events` برای پذیرایی رویداد. شماره‌های فارسی، عربی و انگلیسی، شمارهٔ ثابت یا همراه ۱۱ رقمی ایران و پیش‌شماره‌های `+98` و `0098` پذیرفته و به شکل `0…` تبدیل می‌شوند.

سرویس باید همهٔ ورودی‌ها را دوباره اعتبارسنجی کند، محدودیت طول و تعداد درخواست داشته باشد و فقط پس از ذخیره یا تحویل واقعی درخواست، پاسخ HTTP موفق همراه با JSON زیر بدهد:

```json
{ "ok": true }
```

برای خطا از وضعیت مناسب HTTP استفاده کنید؛ پاسخ موفق صوری ندهید. اگر دامنهٔ مقصد متفاوت است، CORS و درخواست `OPTIONS` را برای مبدأ سایت و هدر `Content-Type` تنظیم کنید. رمز، کلید API و اطلاعات محرمانه را داخل فایل‌های عمومی قرار ندهید؛ آن‌ها باید در سرور بمانند. سمت کاربر، تأییدنشدن ارسال، قطع شبکه و مهلت ۱۵ ثانیه‌ای به پیام خطای فارسی منجر می‌شود.

پیش از فعال‌سازی عمومی، ارسال واقعی، ثبت در مقصد، خطای سرور و محدودیت درخواست را آزمایش کنید. کارهای باقی‌مانده در `RELEASE-CHECKLIST.md` آمده است.
